# Постоянное выполнение СЯ без личного компьютера

Состояние17.11.2026. Дмитрий разрешил аварийное локальное восстановление DeLux,
но потребовал самостоятельный механизм. Локальный прогон не закрывает это требование.

## Подтверждённый блок

Прямой OpenAI с текущего production46.19.66.244 возвращает403
`unsupported_country_region_territory`. Работающий локальный вызов не подтверждает
работоспособность production. Сергей ещё не предоставил рабочее место исполнения.
GigaChat отказывает фильтром на части обычных строительных товаров; смена на
официальный api.giga.chat/v1, JSON Schema и короткие запросы отказ не устранили.
Увеличение таймаутов не исправляет отказ провайдера.

## Выбранное направление

Постоянное серверное место исполнения модели в поддерживаемом провайдером регионе
и с подходящими условиями аккаунта. Это выделенная управляемая служба, без личного
компьютера, интерактивного входа или зависимости от Codex-чата. Текущие БД, кабинеты,
права, MPStats и интерфейс остаются в OptiCards. Перенос всей БД ради модели не нужен.

Сергей должен предоставить конкретную инфраструктуру и допустимый способ доступа.
Нельзя считать неподтверждённый прокси рабочим решением или переключать production
на403. Если отдельная служба/регион не подходит по условиям провайдера, требуется
другой доступный с сервера провайдер с проверкой того же реального набора товаров.

Контракт будущей службы: backend-аутентификация, TLS, ограничение входов, только
факты товара и запросы, без CRM, паролей или marketplace-токенов. Идентификатор
операции включает кабинет/пользователя/хеш фактов/модель/набор запросов. До внешнего
вызова операция сохраняется; ответ фиксируется до подтверждения выдачи. Повторное
чтение результата по тому же идентификатору не оплачивает модель заново. Неизвестный
исход внешнего вызова виден оператору; обещать exactly-once без поддержки провайдера
нельзя. Таймаут, очередь, Retry-After и состояние операции доступны отдельно.

Существующий `OPTICARDS_LLM_API_BASE` позволяет задать совместимый backend endpoint,
но сам по себе не создаёт эту службу, долговечную очередь или поддерживаемый регион.
Ключи передаются через защищённый backend-конфиг, не через чат/git/UI. Настройки
моделей и безопасного переключения: [llm-model-routing.md](llm-model-routing.md).

## Что уже исправляет код OptiCards

- Независимое решение на каждый запрос в компактном формате, проверяемая цитата.
- Корректные строки неполного ответа сохраняются; повторяются только оставшиеся.
- Уменьшившаяся порция GigaChat растёт обратно; прежнее залипание1–4 устраняется.
- Менеджер использует существующие слоты провайдера, одинаковый scope кеша
  выполняется последовательно. Для MPStats сохраняется один шаг получения
  источника одновременно. Прогресс, источник и ручные решения переживают
  перезапуск; отказ провайдера не становится ложной готовностью.

Эти изменения повышают надёжность очереди, но не создают отсутствующий доступ.

## Приёмка постоянного пути

1. Из фактической серверной службы выполнены реальные completions, включая ранее
   отказавшую пену и полный734-запросный источник; схема/цитаты/все строки валидны.
2. Личный компьютер выключен, браузер закрыт. Набор доводится до сохранённых
   черновиков без Codex и без ручного повтора; время/usage измерены на полном наборе.
3. Перезапуск после завершённой порции продолжает оставшиеся запросы и использует
   кеш. Потерянный ответ службы/429/503 не создают повторных операций; неизвестный
   исход внешнего вызова явно останавливается. Нет бесконечных повторов403/refusal.
4. Проверены изоляция двух кабинетов/пользователей, изменение фактов и поздний ответ
   после отмены. Ручные включения, исключения и согласованные итоги сохраняются.
5. Перед переключением — idle/recovery guard, SQLite backup, штатный deploy,
   проверка реального provider/model. Откат конфигурации сохраняет прежний кеш;
   дорогого автоматического fallback или скрытой смены модели нет.

Открытая зависимость: доступное постоянное серверное место исполнения от Сергея.
Передача этого документа не означает, что оно уже настроено или проверено.
