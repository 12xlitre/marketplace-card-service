# Подключение Ozon Seller API

Обновлено: 2026-10-27.

Из общего списка: `Клиенты → Добавить клиента → Маркетплейс: Ozon → Ozon Seller API`. Введите название кабинета, выберите охват и команду, укажите Client-Id и API-ключ. Предварительный WB-кабинет не требуется. Выбор Ozon доступен текущим участникам Ozon beta; её видимость не расширена. При смене маркетплейса введённый ключ очищается.

Подключение работает **только на чтение**: проверяет доступ и загружает товары в OptiCards. Карточки, цены и остатки в Ozon не изменяются. Для Ozon без API сохраняются кабинет и источник; загрузка из MPStats запускается отдельно в Ozon-разделе, WB-загрузчик не вызывается.

Список выбранных SKU можно вставлять столбиком, через пробелы, запятые или точку с запятой. Обе формы подключения приводят его к одной строке источника, отделяя комментарий явной подписью. Старые сохранённые списки с числовыми SKU на отдельных строках также читаются целиком; отсутствие любого выбранного SKU блокирует частичный импорт.

Внутри существующего клиента: `Клиент → Ozon → Подключить Ozon → Ozon Seller API → Проверить и создать`. Для всего кабинета ссылка и SKU не обязательны; при выборе отдельных карточек нужен список SKU.

В существующем Ozon-кабинете: `Настройки кабинета → Подключение Ozon Seller API`.
Пользователь вводит Client-Id и API-ключ своего магазина, затем нажимает `Проверить и сохранить`.
При замене ключа вводятся оба значения. Сохранённые значения обратно в браузер не возвращаются.

Проверка доступа читает список товаров и сообщает их количество. При API-создании кабинета теперь также загружаются карточки; для существующего кабинета форма после сохранения ключа запускает отдельный запрос загрузки. Контракт импорта — [Карточки Seller API](ozon-seller-cards.md). SEO-генерация и публикация этим действием не запускаются. Соответствие продавца выбранному клиенту пользователь проверяет при вводе доступа; один ответ списка товаров не подтверждает соответствие Seller ID из ссылки Client-Id ключа.

## Контракт

`POST /api/portals` с `mode: "api"`, `marketplace: "Ozon"`, `clientId`, `apiKey`, именем и `scope` получает список и данные карточек, затем создаёт кабинет вместе с карточками и зашифрованным подключением одной транзакцией. `clientName`, `teamRoles`, `storeUrl`, `manualSource` передаются обычными полями создания; для `scope=selected` нужен `manualSource` со списком карточек. Требуются права управления кабинетами либо доступ Ozon beta. Успех — 201, `portal` и `productCount`, без ключей. Ошибки проверки, дублирование аккаунта, неизвестный сотрудник или ошибка шифрования не оставляют пустой кабинет. Команда наследуется только из фактических назначений клиента. Повторные проверки при создании ограничены по пользователю интервалом 10 секунд и защитой от параллельного запуска.

`GET /api/portals/<portal_id>/ozon-connection` требует сессию, доступ к кабинету и marketplace Ozon.
Возвращает только `connection.hasCredentials`, `connection.status`, `connection.lastCheckedAt`.

`POST /api/portals/<portal_id>/ozon-connection` требует право редактирования этого Ozon-кабинета:

- `action: "connect"`, `clientId`, `apiKey` — проверить новый доступ и сохранить только после успеха;
- `action: "check"` — проверить уже сохранённый доступ без отправки ключа из браузера.

Успех: метаданные подключения и `productCount`. `lastCheckedAt` — UTC SQLite timestamp; интерфейс отображает его по Москве.
При проверке сохранённого ключа неуспех записывается в его статус. Неудачная замена не меняет прежнюю запись.
Повторная проверка ограничена интервалом 10 секунд и защитой от параллельного запуска внутри процесса.

Типичные коды: `ozon_auth_error` (409), `ozon_rate_limited` (429), `ozon_unavailable`/`ozon_invalid_response` (502), `ozon_check_rate_limited` (429), `forbidden` (403), `secret_storage_unavailable` (500). Некорректный ввод, попытка дублирования аккаунта или смены Client-Id существующего подключения возвращают 400 с безопасным кодом.

## Хранение и ограничения

Используется существующая `portal_integrations`, provider `ozon`. JSON с Client-Id и API-ключом зашифрован AES-GCM с AAD `portal:<id>:integration:ozon`. В `external_key` хранится digest Client-Id для проверки повторной привязки. Новых таблиц и миграций нет.

В транзакции проверяются дубликаты аккаунта и неизменность Client-Id у существующего подключения. Перенос другого магазина в существующий кабинет не выполняется автоматически. Результат медленной проверки не может пометить заменённый ключ проверенным: обновление ограничено digest прочитанной версии.

Карточки, задачи, текущие черновики и `api_connected` кабинета не меняются. Общие WB-механизмы не используются для Ozon. Доступ из env другого магазина не подставляется.

Транспорт фиксирован: TLS к `api-seller.ozon.ru`, только `POST /v3/product/list` с лимитом 1. Redirect не поддерживается. Connect timeout 5 секунд, socket timeout 15 секунд, максимум три попытки при сетевой ошибке, 429 или выбранных 5xx. `Retry-After` учитывается; если ожидание больше 5 секунд, управление возвращается пользователю без преждевременного повтора. Ответ ограничен 512 KiB. Тело ошибок и заголовки авторизации не логируются и не возвращаются клиенту.

Метод основан на сохранённой рабочей API-обвязке проекта Даши. Официальная страница Ozon при проверке вернула redirect loop. Живые read-запросы подтверждены для HoneyBear 2026-10-19: получены все 33 карточки, их данные и справочники характеристик.

## Premortem подключения

Решение: дать пользователю вводить доступ к Ozon при создании или через существующий кабинет, с проверкой и сохранением в текущем хранилище.
Оценки S/O/D — аналитические, по шкале 1–10; RPN = S × O × D, остаточные оценки действуют при выполнении указанных условий.

| Возможный провал через 6–12 месяцев | S/O/D → RPN | Условие снижения риска | После |
| --- | --- | --- | --- |
| Ключ попал в API-ответ, браузерное хранилище или журнал | 10/5/7 → 350 | Метаданные без ключей, шифрование пары, безопасные ошибки и события, браузерная проверка | 10/2/2 → 40 |
| Пользователь поменял подключение чужого кабинета | 10/5/6 → 300 | Проверка edit/read до чтения ключа и сети, AAD кабинета, негативные тесты | 10/2/2 → 40 |
| Под существующими карточками незаметно сменили магазин | 9/5/6 → 270 | Фиксация Client-Id существующей связи, защита от дублирования в транзакции | 9/2/2 → 36 |
| Ошибка подключения оставила пустой кабинет | 7/6/4 → 168 | Проверка до записи, кабинет и encrypted-доступ в одной транзакции, тесты auth/encryption/team rollback | 7/1/2 → 14 |
| Неудачная замена уничтожила рабочий доступ | 8/6/5 → 240 | Проверка до записи, транзакция, тест неизменности старого ключа | 8/2/2 → 32 |
| Проверка стала бесконечно ждать или повторять ошибки | 7/6/5 → 210 | Таймауты, три попытки, отсутствие retry 401/403, Retry-After и ограничение повторов | 7/2/3 → 42 |
| Сохранение ключа ошибочно включило WB-импорт или публикацию | 9/4/5 → 180 | Отдельный маршрут и provider, неизменность api_connected/снимка, фиксированный read endpoint | 9/1/2 → 18 |
| Поздний ответ старой проверки затёр статус нового ключа | 7/5/5 → 175 | Проверка digest версии и защита параллельного запуска | 7/2/2 → 28 |
| Доступ к списку товаров приняли за готовность всей SEO-услуги | 6/6/4 → 144 | Явное описание границы проверки в форме и документации | 6/3/2 → 36 |

Вердикт подключения: **GO с условиями** — ввод и проверка списка товаров разрешены. Последующее расширение на импорт карточек отдельно разобрано и проверено в [Карточки Seller API](ozon-seller-cards.md); массовая SEO-подготовка остаётся следующим этапом.
