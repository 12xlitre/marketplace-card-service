# Project Memory

Устойчивые договоренности и решения проекта.

- `product_visual_first.md` — продукт делаем через визуальный прототип и пошаговое уточнение процесса.
- `product_store_onboarding.md` — выбор Wildberries/Ozon при создании, обязательный список nmID для выбранных WB API карточек; API или ручной режим, Ozon только для чтения.
- `backend_auth_and_sessions.md` — backend-only auth, сессии с разным TTL и remember-me, восстановление состояния после refresh.
- `backend_portals.md` — метаданные и отложенная загрузка карточек кабинета, состав проекта в SQLite/backend API; отдельное право создания для Насти, справочник команды и привязка нового кабинета к клиенту.
- `backend_wb_readonly.md` — WB API подключение через backend, токены только env/demo или encrypted per portal, чтение карточек и строго ограниченная ручная публикация принятого контента.
- `ops_production_deployment.md` — OptiCards развернут на `opticards.weboptai.ru`, прод-обвязка живет на сервере; новые Python-модули требуют явного включения в образ.
- `product_wb_characteristic_values.md` — правила по значениям характеристик WB: где есть официальный справочник, где только подсказки из карточек, и почему нужен MPStats.
- `product_approval_workflow.md` — роли согласования, отдельный доступ руководителя к сбору СЯ, хранение задач/событий, правило soft reset анализа при обновлении WB и кабинетная XLSX-выгрузка итогового контента.
- `product_mass_workflow.md` — постоянные правила массовой обработки: источники, конкуренты, факты без хештегов, тексты, Excel, проверки, пачки и согласование; границы независимого компилятора и очистка истории по поручению владельца 03.11.2026. Текущая версия файла и открытые вопросы — в WORK.md.
- `../automatic-seo-workflow.md` — автоматическая оптимизация WB/Ozon: выбор задачи, конкурент, итоговый Excel, версии/согласование, прогресс/ETA, уведомления Насте в Битрикс24, привязка к плану, источники и хранение.
- `product_marketplace_architecture.md` — уровень `Клиент`, WB/Ozon для всех пользователей с прежней изоляцией кабинетов и глобальным обзором руководителя.
- `product_semantic_core.md` — правила СЯ: ранжирование, полный `allKeywords`, фоновый подбор WB/Ozon с восстановлением/отменой и кешем решений, источники MPStats и клиентское согласование.
- `product_reports.md` — вкладка отчетов внутри кабинета селлера, явный выбор периода и первый клиентский WB XLSX-отчет.
- `product_work_periods.md` — отчетный период, версии/подтверждения; сквозной календарь в палитре OptiCards: аккаунт назначает дни, специалист перетаскивает в ячейку и выбирает только длительность; фирменный PDF по образцу09.11.2026.
- `../content-task-workflow.md` — требования09.11.2026: принятие плана аккаунтом с подтверждением, календарь8ч, массовое СЯ и клиентское согласование по задаче, два контентных файла, PDF и переписка через сделку Б24 без почтовых паролей; контракт реализованного процесса и ограничения подключения.

- `product_crm_correspondence.md` — переписка кабинета через сделку Б24, без почтовых паролей: права, явная привязка, чтение CRM, отправка точного файла и uncertain без повтора.
