# Клиентская переписка через сделку Б24

Решение Дмитрия09.11.2026: почтовые SMTP/IMAP логины/пароли не передаются
OptiCards. Используется существующий вебхук Б24; ящик уже подключён к Б24.
Scope mailservice — настройки почтовых сервисов, а переписка сделки требует CRM.

Уточнение Дмитрия 10.11.2026: кабинет WB/Ozon → Почта показывает карточки
сделок воронки «Аккаунтинг» (CATEGORY_ID=11). Аккаунт видит только сделки, где
он ответственный: workflow_people.bitrix_id = ASSIGNED_BY_ID, в том числе при
глобальном обзоре. Без ID Б24 список закрыт с подсказкой настройки. Поиск по
названию/номеру выполняется в Б24, страницы по 50, завершённые включаются явно.
Выбор карточки → просмотр названия/контакта → явная привязка; автоматического
сопоставления по имени нет. Admin видит все сделки этой воронки и может явно
привязать любую. Дмитрий 10.11.2026 подтвердил такую возможность для себя,
Кристины, Оксаны и Сергея, включая обзор и создание кабинетов. Аккаунту Светлане
остаётся выбор только своих сделок. Пользователи полного доступа используют
административную роль; фактическая настройка учётных записей — в WORK.md.
само чтение руководителем не даёт право изменять привязку чужого кабинета.
Чтение только аккаунту кабинета/admin и global lead, запись аккаунту/admin;
tech запрещено независимо от глобального доступа или случайной team manager роли.

Письма читаются непосредственно из crm.activity.list с exact BINDINGS deal2/id,
TYPE_ID4; только CRM письма выбранной сделки, не весь почтовый ящик. UI45с при
открытой видимой вкладке, ручное обновление, страницы по ID. HTML→plain text,
никаких удалённых картинок/пикселей, исходных SETTINGS или произвольных URL файлов.
Входящие вложения открываются в Б24. Ответ — новое письмо с Re и цитатой;
RFC In-Reply-To сейчас не задаётся. UI не заменяет полноценный почтовый клиент.

Новые письма/план/СЯ/два контентных файла: единый composer, явная кнопка отправки,
crm_email outbox, crm.activity.add EMAIL4/out2/completedY. Сохраняется точный
fileSha и UUID+origin+deal привязки; права/версия проверяются вновь worker-ом.
SMTP UI убран, старые SMTP очереди имеют совместимый прежний транспорт.
Повтор requestId с другим телом409; неопределённая отправка/рестарт → uncertain,
никогда автоматический повтор. Проверка отправки в Б24 только подтверждает
положительно найденный ORIGIN_ID, не разрешает resend по отсутствию результата.
При pending/sending/uncertain привязку изменить/снять нельзя.

Activity ID означает принятие Б24, не прочтение/согласование и не гарантию IMAP
Sent. Ответы появляются после синхронизации почты Б24 и привязки к сделке.
Для первой реальной проверки нужен собственный тестовый адрес и явное поручение;
никакие реальные письма не отправляются в ходе обычной проверки выпуска.

Runtime остаётся в server.py, additive workflow_crm_links cascade при удалении
кабинета. Новый backend модуль/инфраструктурные зависимости не нужны. Контракт
и маршруты: ../content-task-workflow.md. Текущая конфигурация/выпуск — в WORK.md.
